# وِصال AI (Wisal AI)

منصة ويب عربية لتحليل أسلوب الخطاب وتكييف طريقة الإيصال مع الجمهور باستخدام Gemini، مع الحفاظ على المعنى وربط النتائج بالمصادر المعتمدة فقط.

## روابط الإنتاج
- الواجهة: https://wisal-ai.onrender.com
- API: https://wisal-ai-api.onrender.com
- فحص الصحة: https://wisal-ai-api.onrender.com/api/health

> رابط الواجهة المعتمد للمشروع هو `wisal-ai.onrender.com`. لا تعتمد روابط نشر قديمة مثل `wisal-ai-v8n2.onrender.com` عند الاختبار.

## البنية
- `index.html`: واجهة المستخدم والتفاعل مع API.
- `server.js`: خادم Express، تحليل Gemini، الاسترجاع من المصادر المعتمدة، CORS وواجهات API.
- `SOURCES.md`: سياسة المصادر التسعة المعتمدة.
- `package.json`: إعداد تشغيل Node.js.

## التشغيل المحلي
1. ثبّت Node.js 20 أو أحدث.
2. شغّل `npm install`.
3. عرّف `GEMINI_API_KEY` في بيئة التشغيل.
4. اختياريًا عرّف `GEMINI_MODEL` (الافتراضي: `gemini-2.5-flash`).
5. شغّل `npm start`.
6. افتح `http://localhost:3000`.

## API
- `GET /api/health`: حالة الخدمة وتهيئة Gemini وسياسة المصادر.
- `GET /api/sources`: المصادر التسعة المعتمدة.
- `POST /api/analyze`: تحليل النص وإرجاع الانطباع ونقاط القوة والتحسين والصياغة والمصادر المستخدمة فعليًا.

## قواعد الإنتاج
- لا تعرض الواجهة نتيجة AI تجريبية على أنها نتيجة حقيقية.
- لا يُعرض مصدر إلا إذا كان ضمن المصادر التسعة المعتمدة وتم استرجاعه واستخدامه فعليًا.
- لا تُخزّن مفاتيح API في GitHub أو الواجهة؛ تبقى في متغيرات بيئة Render.
- الواجهة تتصل في الإنتاج بـ `https://wisal-ai-api.onrender.com`.
- حد النص 1500 كلمة.
- وِصال يحسّن أسلوب الإيصال ولا يصدر فتوى.

## النشر على Render
يوجد خدمتان مرتبطتان بفرع `main` مع Auto Deploy:
- Static Site باسم `wisal-ai` للواجهة.
- Web Service باسم `wisal-ai-api` للخادم.

أي commit إلى `main` يطلق النشر تلقائيًا للخدمتين.
