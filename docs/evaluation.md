# القياس والتحقق

## تقييم تقني
`npm test`: مجموعة قواعد قابلة لإعادة الاختبار. `npm run test:live`: 3 حالات عادية و3 حالات ملزمة، كل حالة مرتان، مع نتائج HTTP والتوقيت وحالة الفحوص. النصوص مصطنعة وعامة. نتائج التنفيذ الفعلية في docs/evidence، بما فيها محاولة أولية كشفت مشكلة توافق حقول الوكيل وتمت معالجتها.

النجاح التقني يعني اكتمال السيناريو المحدد أو اتخاذ قرار الإحالة المتوقع، وليس صحة جميع الادعاءات أو تحسن الإقناع. لا تُجمع الحالات المرفوضة ذات زمن قريب من الصفر مع التحليل لاستخراج متوسط مضلل لزمن التحليل.

## مقارنة مرجعية محددة
البديل: رسالة الكاتب الأصلية دون مراجعة أسلوبية آلية. المقارنة التقنية الحالية: الأصل والاقتراح وقرار الفحوص لكل طلب. المقارنة البشرية المقترحة: تقييم أعمى للنصين دون معرفة ما حسنه وِصال؛ تجنب قياس المعتقد الديني أو جمع بيانات حساسة.

## دراسة أثر لم تُنفذ بعد
عينة مقترحة: 5–10 كتّاب و5–10 قراء بالغين باختيار طوعي ونصوص عامة. مقياس 1–5 للوضوح وملاءمة الأسلوب واحترام الأسئلة، ومراجعة منفصلة لحفظ المعنى. يسجل وقت إعداد الرسالة ونسبة الاقتراحات المقبولة بعد مراجعة. النتائج لا تُملأ من توقعات النموذج.

| المؤشر | طريقة الحساب | الحالة |
|---|---|---|
| اكتمال المهمة | مهام مكتملة / مهام اختبار | يقاس آليًا في سجل التقييم |
| قرارات الحالات الملزمة | قرارات متوقعة / حالات حرجة | يقاس آليًا |
| زمن التحليل | زمن كل طلب تحليل، منفصل عن الرفض | يقاس آليًا |
| وضوح الرسالة وملاءمة الجمهور | فرق تقييم أعمى قبل/بعد | لا توجد بيانات بشرية بعد |
| حفظ المعنى | قرار مختص على النصين | لا توجد مراجعة بشرية مكتملة بعد |
| وقت عمل الكاتب | زمن الإعداد بالطريقة الحالية مقابل وِصال | لا توجد بيانات بشرية بعد |

لا يقدم العرض نسب تحسن أو نسب رضا غير مقاسة. الدراسات المستقبلية لا تُصاغ كمنجزات.
